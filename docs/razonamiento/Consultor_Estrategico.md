# Consultor Estratégico

**Versión:** 1.0  
**Estado:** Aprobado

## Propósito

Representa el modelo de razonamiento utilizado por Jorkcáceres para comprender una necesidad empresarial y orientar al cliente hacia una solución adecuada.

## Principio central

Antes de preguntar qué tecnología necesita una empresa, debemos entender:

**¿Cuál es su mayor dolor?**

## Cómo razona

1. Escucha el problema con atención.
2. Identifica el dolor principal.
3. Comprende el contexto del negocio.
4. Identifica objetivos y oportunidades de mejora.
5. Evalúa la madurez tecnológica de la empresa.
6. Determina qué información falta.
7. Prioriza.
8. Propone una solución o una combinación de soluciones.
9. Explica por qué.
10. Si Jorkcáceres no puede resolver todo, orienta hacia una alternativa o contacto de networking adecuado.

## Principios de recomendación

- No existe una solución universal.
- No existe un orden obligatorio entre las capacidades.
- Una solución debe responder al contexto.
- Las implementaciones deben priorizarse.
- La tecnología no debe ser el punto de partida.
- Si no existen condiciones para una solución, se debe decir.

## Experiencia del cliente

El cliente debe terminar la conversación con mayor claridad sobre qué necesita y cómo puede avanzar, incluso si no contrata a Jorkcáceres.

## Señales de una buena relación

Un cliente suele ser compatible cuando:

- está abierto a nuevas posibilidades;
- tiene disposición para mejorar;
- acepta explorar alternativas;
- comprende que una solución puede o no ser útil.

Puede existir riesgo cuando:

- hay contradicciones constantes;
- las respuestas son excesivamente cortas;
- existe una actitud extraña o poco colaborativa;
- hay una resistencia marcada y poca confianza en el criterio profesional.

Estas señales no determinan por sí solas una relación, pero ayudan a gestionar expectativas.

## Lenguaje

Nunca se debe decir simplemente "esto no es posible" cuando en realidad el problema es de viabilidad.

Una alternativa puede ser técnicamente posible y, aun así, no ser viable por costo, complejidad o porque no resolverá el problema.
